# Memory and ownership plan

The selected pack and original component revisions are pinned in
`provenance/models.lock.json`. This ledger distinguishes published file sizes,
header-derived tensor bytes, prospective allocations, and measured hardware
allocations. Only the first two can be established on this CPU development host.
`provenance/allocation-plan.json` is generated by the inventory/planner tooling.

## Ownership

Default half-open ranges: A `[0,18)`, B `[18,23)`, C `[23,40)`.
Validate exactly three nonempty, contiguous stages covering the model. Both
Engram layers 1 and 14 stay on A. Embedding and vision belong to A. C owns the
head, final collapse/norm and all draft components; shared embedding required by
DSpark is an explicit additional C allocation. Never allocate a worker Engram
table merely because other tensors share its file.

For every compressed consumer, derive the latest preceding KV and index source
from actual config. B needs source-14 KV/index K and top-k state from A; C needs
source-20 KV/index K, index-20 top-k and candidate blocks from B. C owns index
queries 24/28/32/36 but those use source-20 index K rather than four independent
full-length K caches. Every stage still owns per-layer SWA, compression and
transactional state. Register each shadow using logical positions and independent
physical slot maps; never transmit source pointers or physical slot numbers as
recipient addresses.

## Persistent state arithmetic

At 1,048,576 positions, BF16 KV width 512 plus BF16 index K width 128 costs
1280 bytes per stored logical row. Sources 2/8/14 are half-rate; source 20 is
full-rate. Primary arrays total 3.125 GiB; with source-14 and source-20 shadows:

| Stage | Primary/shadow KV+index K bytes | GiB |
| --- | ---: | ---: |
| A | 2013265920 | 1.875 |
| B | 2013265920 | 1.875 |
| C | 1342177280 | 1.250 |
| Total | 5368709120 | 5.000 |

This is not total attention memory and not evidence a qualified BF16 backend exists.
Also budget SWA rings for every owned layer, compression pairs, per-row validity
and generation maps, sparse top-k/candidates, request-local workspaces, attention
sink and RoPE state, journals and draft state. Include padding/alignment and
allocator overhead once concrete layouts are implemented. Capacity is eager;
logical validity grows inside the fixed pool without reducing the advertised
context.

## Actual weights and missing metadata

Published EXL3 file bytes: 210742161222 (43 files); tensor index total payload:
210721837240. Original Engram file sizes are 101535150936 and 101537926640
bytes, with publisher SHA-256 in models.lock.json. These are separate external
files, not extra local Codex downloads. Each deployment machine can retain the
full EXL3 pack on SSD, but only owned tensor ranges are materialized.

The simple routed estimate omits scale vectors, codebook markers and all other
components. Quantization metadata covers only 187106 of 192495 index entries,
so complete per-stage totals require all bounded shard headers. Inventory must
validate dtype × shape against offsets, file lengths, missing/duplicate names,
K-map vs physical trellis shape, and the union of owned tensors. Unknown bytes
remain unknown; they never become an implicit zero.

The planned tensor manifest records file/revision/hash, name, dtype, shape,
data offset, byte length, component, owner and any duplicate physical copies.
Header reads are bounded, range-only HTTP requests. Reject servers that ignore
Range; do not fall back to a complete weight download. Published payload hashes
are recorded but are only verified when the user's local inventory tool hashes
the actual files.

The completed header inventory yields these owned pack payload totals (including
draft weights assigned to C): A 96469307296 bytes, B 17602641264 bytes,
C 96649888680 bytes. B's components are 17072478720 routed expert bytes,
88696380 shared expert bytes, 39436600 layer-other bytes and 402029564 attention/
index bytes. Original Engram table+scale payloads on A add 202758032400 bytes.
The external shard files also contain original projections that are already
represented by EXL3 tensors; those original projections are not loaded twice.
Physical trellis inspection, including tensors absent from quantization metadata,
finds K2/K3/K4/K5/K6/K8. Header-derived ownership does not imply simultaneous
resident allocation of the desktop cold weights or disabled draft module.

## Exact replay schedule to qualify

A bounded candidate schedule uses two encoder passes, rather than retaining
80 GiB of full-prompt activations. Pass 1 streams exact encoder layers 0–19 and
produces the complete layer-20 global KV/index source using its input projection.
After a source-20 completeness barrier, pass 2 recomputes encoder chunks and
executes all decoder layers 20–39 in prompt order against that fixed global
source. Keep only bounded activation chunks, local SWA rings, compression state
and the eager source pools. Reset phase-local rings correctly, preserve absolute
compression parity and avoid double-advancing token history/Engram/RNG state.

This is a design proposal for the adapter, not implemented or proven exact yet.
It requires source-level verification of every stage/phase dependency, pure
operation fixtures and comparisons to the full pinned reference. It may require
additional encoder recomputation; no throughput benefit is claimed. If a source
has other dependencies, revise the schedule with explicit state/lifetime evidence.
Do not substitute the upstream last-128-row bounded decoder optimization.

## Admission and lifetimes

B preloads its complete assigned model and mandatory pools before READY, warms
all accepted execution paths, touches pages, and establishes checked Windows
locking/device budgets. Resident-only storage has no inference read-from-file
path and drops backing file handles after preload. WDDM eviction and lock API
guarantees must be investigated on the exact native implementation; preload or
low observed hard-fault counts alone do not prove residency. Refuse admission
when separate host or device budgets cannot meet the documented guarantee.

A/C have bounded local SSD-to-RAM-to-VRAM caches. Each physical copy, pinned
staging buffer and in-flight lease counts against a named budget. A failed read
cannot publish an expert. Eviction cannot recycle leased/DMA-active slots.

FP32 `[rows,4,5120]` activation bytes are 81920 per row per boundary. One
4096-row buffer is 320 MiB; retaining 1M rows is 80 GiB. The initial protocol
caps individual frames at 1 MiB and uses bounded fragments. Select the actual
prefill chunk only after the model adapter workspace ledger exists. Never
allocate `[prefill_rows,1M]` full scores; process sparse/attention work in bounded
rows/tiles. Exact CED replay needs an explicit recomputation/storage schedule.

Record separate boot, warmup, largest accepted prefill, image+prefill, decode,
verification, cancellation, save and restore peaks. Vision may precede prefill
only when its live dependencies and subsequent release are proven. Snapshot
streams use bounded chunks; an in-place restore failure invalidates the session
on every rank rather than claiming the old state is usable. No extra full-state
copy can be assumed on any 32 GiB machine.
# Actual BF16 pool accounting

`cache_pool.DeviceRowPool` now allocates and touches the BF16 payload eagerly,
alongside int64 device generations, bounded device undo rows and fixed host
logical/generation arrays. Those arrays and journal/scratch reservations count
in addition to the source/shadow payload arithmetic. Pool construction refuses
an insufficient explicit admission. Allocation and `cuda.synchronize` alone do
not prove WDDM residency or whole-process fit; those remain hardware gates.

Source/shadow slot offsets are independent. GPU scatter checks existing local
generations; the pool backs up every target before writing, advances local
generations after success, and restores rejected writes in reverse timeline
order. Failed tentative writes block consumption until a complete abort. A
metadata or backup failure before scatter cannot create a valid undo entry.
The global stage transaction and replica protocol still need to bind these pools
into the actual model. `selftest-cuda` contains a small real-GPU partial-prefix
and ring-overwrite regression; it has not executed on this host.

## Stage C draft embedding replica

The draft graph shares the target's input embedding semantically. Stage C now
admits an explicit local replica of the publisher-pinned `embed.weight`:
129280 × 5120 × 2 = 1,323,827,200 bytes (about 1.23 GiB). It is a permanent
native BF16 device weight and counts in addition to C's canonical owned payload.
The selective loader permits this one replica only on C and still verifies its
original shard/header/full-file hash. No other unowned tensor becomes readable.
The replica requires full whole-process/device admission before allocation;
the five-GiB source/index/shadow estimate does not include it.

## Complete header-derived runtime admission

`runtime_memory.plan_runtime_memory` reconciles all 47,900 packed matrices and
895 original native tensors, plus C's one embedding replica. It derives every
expert bundle's aligned storage and requires every owned expert, including the
128-expert draft layers. Native destination dtypes, permanent packed arenas,
BF16 pools, device generations, host maps, FP32 RoPE/pair state, checkpoints,
bounded workspaces and separate host/device headroom all count before sizing
the expert arena. Missing expert bundles and insufficient host/device budgets
fail admission. This is prospective arithmetic; hardware peak measurements
remain necessary.

B uses one shared 1 MiB CUDA-pinned transfer tile for boot, native and expert
uploads. A checked native CPU copy moves bytes directly from VirtualLock pages
to that tile; no pageable payload copy or whole-store CUDA registration occurs.
Registering the complete 16.4 GiB store could create unnecessary WDDM/shared
memory pressure on a 32 GiB laptop. The canonical owned store remains locked,
and its original file source remains closed. After preload, QueryWorkingSetEx
checks the Valid and Locked bits of every allocated page in bounded batches.
The 18 GiB-scale host lock and actual CUDA transfer remain hardware gates.

Native ABI 2 adds a real CUDA-LUID-to-DXGI adapter query for local/nonlocal
WDDM budgets and usage; physical host availability comes from Windows. The
budget guard compares nonlocal usage to its pre-allocation baseline plus known
transfer staging and refuses execution under pressure. These counters are not
an absolute guarantee that Windows can never evict a GPU allocation. Native
Windows compile/import and real-hardware budget/residency qualification remain
pending for the new telemetry path.
